# 第一階段 D-3 驗收報告

2026-10-13，dev 分支；未提交 commit、未推送，未遷移正式存檔，正式永久角色與正式三人離線仍關閉。

## 1. 四角色資料與入口

帳號的永久角色、槽位及舊副本遷移上限改為四名；每個隊伍仍最多三人，沿用既有等級解鎖隊伍欄位規則。建立角色使用 UUID；移動槽位不換 ID；刪除後保存退役 ID 與成長封存，新角色不能沿用舊 ID。

四名角色共用原帳號背包，各自保留裝備欄。裝備穿戴限制、詞綴、符文及唯一實例維持原政策。刪除需先卸下裝備，先結算該角色待領收入，移除所有隊伍引用後才能封存。尚未完成的工作仍阻止刪除／重設，不能跳過收益直接刪角色。

切換主角在等待保存前先捕捉永久 ID，避免等待期間槽位改變後選到另一人。每個分頁保留自己的主角選擇；帳號的 activeMainId 是最後一次保存的選擇，不將其他分頁的主角選擇誤作本頁戰鬥身份。查看隊友仍是獨立只讀操作。

## 2. 隊伍資格與戰鬥占用

IndexedDB 帳號紀錄新增 farming 狀態，與角色／編組共用既有交易邊界：owners 按永久角色 ID 指向場次 token；sessions 保存隊長、參戰 ID、模式、狀態、epoch 及時間；eligibility 保存單人離線資格與起算界線。

單人資格看所有實際多人成員引用，而非只看當前主角的編組：加入任何隊伍後，即使隊長不戰鬥，仍不能單人掛機。把單人場改叫 party，但只帶自己，也不能繞過此限制。隊伍的正常掛機可運作。

保留既有「各角色保存自己編組」的資料結構，不自行刪除多隊引用。同一角色可以被待機編組引用；真正開始戰鬥時，每個角色只有一個占用，重疊編組不能同時使用同一角色。

跨分頁角色鎖使用 Web Locks，先按角色 ID 排序取得，取得後再交易驗證占用、版本及收益工作。角色資料的寫入須帶有效場次 token；過期版本、錯誤 token、直接改編組的舊相容存檔均拒絕。不是僅禁用按鈕或使用 localStorage 先讀後寫。

## 3. 入隊前結算

暫停在線事件 → 保存 HP／MP／職業資源與冷卻 → 停止原單人場次 → 恢復原待領工作 → 沿用原公式結算 → 確認交易成功 → 交易更新隊伍引用。

對方在另一分頁單人掛機時，以 BroadcastChannel 請原分頁保存並停止。回覆成功且角色鎖真正釋放後，才完成入隊。保存失敗、無法停止、原工作不相容或角色仍被占用時，不完成入隊、不清除收入。通訊無回覆也不代表可以強制奪取角色；仍必須通過原鎖與交易檢查。

停止原場與結算成功、但後續入隊失敗時，已合法結算的收益保留，重試不再發放；不宣稱整個入隊流程成功。

## 4. 舊收益與離隊界線

新規則生效前，舊程式按各角色 lastActiveAt 計算單人離線，並未記錄歷史入隊時刻。新資料層保留 legacyDebts 的原起點與固定切換截止時間，先按原政策結清該段，再允許角色參戰或變更成長。主角／隊伍的實際操作順序決定處理順序，不將舊收益直接歸零。

新規則生效後，入隊／離隊均保存明確界線。成功離隊才恢復單人資格，新的單人起算點不得早於該次成功交易時間；仍被其他隊伍引用時，尚未恢復單人資格。離隊本身不自動開始掛機，必須真的開始單人戰鬥並在離開時正在戰鬥，才建立新的離線收入資格。不能補領新制度下隊伍期間的單人收益。

隊伍離線仍保留現行收益：teamOffline 記錄真實隊長、成員及起點，結算工作標為 team-legacy，沿用原主角單人計算函式。只給原主角既有收入，不把隊友經驗或掉落乘倍，未開啟第四批 A 的三人正式模擬。這是舊隊伍收入的相容接線，並非容許隊員另外開單人場。

再開始掛機、換主角、入隊／離隊、刪除或重設時，先處理相關待領票。收益、背包、藥水及票據完成狀態在同一筆交易寫入；準備中的工作保留原快照、時間、種子與上下文。計算防禦增益時讀取收益所屬角色的保存狀態，不能誤用目前頁面主角的增益。

## 5. 非同步與中斷恢复

招募、離隊、切换、開始及停止經同一帳號操作鎖協調，取得後重新讀取權威版本。等待跨分頁回覆期間若主角已改變，舊操作會被拒絕，不先停止新角色的戰鬥。

保存讀取 token 在角色／版本重讀後失效；舊回呼不能拿舊成長資料覆蓋新角色。延遲回呼捕捉主角身份；戰鬥回呼另驗證戰鬥身份，保留合法同場效果，丟棄已換角色／戰鬥的效果。地圖與畫面收尾不被誤當戰鬥效果全部取消。

在線狀態約每 250 ms 在戰鬥事件後保存檢查點，保存 HP、MP、職業資源、護盾、死亡、控制、冷卻及必要動態欄位。恢復或暫停後讀取已保存狀態，不以新最大 HP 免費補滿、不自動復活；原正式敗北回村政策不變。敵方 HP 不因讀回角色狀態而重設。

關閉／重新載入使瀏覽器釋放角色鎖。新頁必須先成功取得全部場次角色鎖，證明舊頁已不再持有，再恢復占用；不靠時間逾期強行清除。原頁仍活著時不會被新頁奪取。同步保存衝突會明確停止並要求重載，不假裝已保存。

已完成場次只保留近期少量摘要；活動場次及待領票保留。已完成收益的 journal 防重複依據不隨場次摘要整理刪除。

## 8. 正式切換仍須注意

- 正式入口與正式存檔完全未切換；本報告不宣稱可以直接自動遷移所有玩家。
- 舊裝備實例或角色身份有歧義時，維持備份及 requires-review，不自行拆分、複製或删除。舊第四批 A 工作須按原政策先恢复。
- 不支援 Web Locks 時，掛機安全接線拒絕啟動，不降級成不安全的 localStorage 競爭檢查。不同裝置／瀏覽器資料同步不在本批範圍。
- 嚴格版本衝突會拒絕保存；不同分頁並行更改共用背包時，可能需要重載，尚未宣稱所有並行互不干擾。
- 強制終止程序不保證最後尚未提交的幾毫秒資料落盤。恢復使用最後成功檢查點，不宣稱 beforeunload 可保證每筆事件保存。
- 重設模型封存與後續登出設定仍是兩筆交易；設定失敗不刪除封存，不假裝兩步全部成功。
- 團隊離線目前仍是舊主角計算；新三人模擬與第四批 B 均未啟用。技能／轉職培養 UI、角色與背包整合 UI、三人經驗分配均未變更。
