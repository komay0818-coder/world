# 三人永久培養：第一階段 B 隔離接線驗收

本批只在 dev 工作區實作，未提交 commit。正式 index.html 未啟用永久角色執行入口，正式 localStorage 存檔沒有遷移。正式三人離線掛機保持關閉。

## 接線範圍與資料流程

隔離入口 tools/permanent-party-playtest.html 使用現有 script.js 與原 UI。永久角色服務提供 getProgress、getCharacterSlots、角色切換、招募、離隊、背包、穿戴與卸下所需的相容讀寫接口。隊伍權威資料只有永久 ID 與順序；展示及戰鬥快照由最新角色資料建立。查看角色不執行切換、地圖變更或離線結算。

讀取永久模型 → 建立帶角色 ID 與讀取版本記號的相容資料 → 原遊戲操作 → 驗證角色與共用背包候選模型 → 單一 IndexedDB 交易保存 → 成功後更新已提交模型。舊讀取中未修改的欄位不覆蓋新值；跨角色讀取記號或同欄位過期修改被拒絕。永久角色、背包及編組同時寫入，舊 slots 不再是權威來源。

裝備維持 instanceId 唯一所有權，保存詞綴、符文與數值。材料與消耗品只在完整 metadata 一致時合併數量；衝突停止遷移。金幣、魔法結晶仍屬原角色，原 accountResources 歸屬不變。穿戴限制共用既有政策。跨角色交換由交易服務支援，未新增 UI。

在線隊伍重建保留既有 actor 物件、HP、MP、資源、控制、DOT、護盾、寵物、死亡與復活時間及技能冷卻。角色成長或編組變更只更新必要屬性，HP/MP 只截至新上限，不免費補滿。戰鬥存檔以永久 ID 尋找角色，槽位移動不寫錯人。共用瀕死保護冷卻隨參戰角色保存與恢復，未改變其既有秒數或觸發規則。

## 正式入口仍保留的舊流程

正式頁面的角色、背包與原離線結算仍使用既有路徑。本批新服務只在明確隔離入口啟用：獨立資料庫 stardust-permanent-stage-b-isolated，隔離頁 localStorage 相容接口寫入新交易服務，sessionStorage 亦隔離。正式頁不會自動讀取或寫入此資料庫。這是本批禁止遷移正式存檔的邊界，不能宣稱正式帳號已切換完畢。

隔離入口不啟用正式離線結算。第四批 A 舊 prepared 紀錄仍須先按原快照、亂數種子及政策安全恢復，再進行遷移；永久模型不容許舊離線 API 回寫 slots。

## 遷移、回滾與多分頁

遷移先保存完整原資料備份，再在同一交易切換權威模型。失敗保留舊來源與備份；重試不重複匯入。實際舊存檔副本驗證：2 名角色、4 件裝備、7 瓶治癒藥水，數量及備份一致；5 個正式 localStorage 關鍵值前後完全相同。

IndexedDB 交易讀取並檢查 revision，整個角色／物品模型原子提交。多分頁同時修改金幣，以及同時穿戴相同裝備，均只有一頁成功，另一頁收到 Concurrent save conflict 並停止後續寫入；裝備仍為 6 件，沒有複製。不能以 localStorage 鎖取代此機制，也不會自動重放過期收益。

結算或保存中的在線定時事件與操作暫停，成功後恢復。保存失敗回到最後已提交模型並凍結寫入，需重新載入最新版本。強制關閉瀏覽器可能遺失尚未提交的最後操作，但不會部分保存角色或背包；頁面關閉提示不是持久化保證。

## 剩餘限制與下一階段

重複裝備 ID、數量不一致、metadata 衝突或尚未完成的舊離線紀錄會阻擋切換；不直接刪除或猜測修復。未保證所有歷史存檔都可自動遷移。正式入口切換仍需獨立核對，不能直接將隔離試玩當成正式帳號。

第二階段需接入按參戰人數平分基礎經驗、兩位小數保存、各角色既有等級衰減及獨立升級。未新增技能、轉職或背包 UI，未改在線平衡，未開始離線第四批 B。本批完成後停止，等待確認。

## 裝備查看反應修正

隔離入口原本在保存期間攔截所有點擊，會吞掉開啟裝備、背包與物品查看操作。現在只讀的裝備／背包入口、物品資訊及關閉按鈕可同步執行；穿戴、卸下等修改操作仍受交易鎖與失敗保護限制。更新隔離 bootstrap 快取版本，正式頁及存檔不變。

新增真實瀏覽器案例刻意在交易 pending 時點擊：裝備立即開啟、立即關閉、卸下仍被阻擋。瀏覽器接線檢查現為 31／31，正式存檔前後相同；角色交易單元案例維持 45／45。
