# 第二階段 A／第四批 A：收益與交易存檔驗收

本批在 dev 開發，正式三人離線入口仍關閉，沒有 commit。新增功能可經隔離的瀏覽器驗證頁執行完整模擬、收益與 IndexedDB 存檔。原有 claimOfflineRewards、在線戰鬥與 localStorage 存檔入口未替換，沒有啟用 Worker、特殊建築、區域壓制或四隻普通怪戰鬥。

## 1. 接入項目與政策來源

- 主角經驗：直接使用 MapExpPolicy.calculate／requiredXp，依現有離線政策使用地圖 normalXp。經驗只發給主角；模擬先完整完成，再在收益草稿中逐隻結算升級，不回頭修改本次戰鬥快照。
- 保留既有離線 Lv30 升級上限；已經超過 Lv30 的角色不會被降回 Lv30。本批沒有把離線升級政策改成在線無此上限的政策。
- 金幣：保留既有離線每擊殺 2 金幣，不改成在線 enemy.gold × 55%。不乘隊伍人數。
- 材料：直接共用第一、二、三章材料政策、VillageUpgradePolicy、PreJobTrialPolicy；沒有另建機率。
- 普通怪其他掉落：直接共用黑森林淨化材料、技能素材、三章配方與第二章符文政策。
- 裝備：直接共用 EquipmentDropPolicy 與其正式 lootConfig／詞綴／插槽政策；平原深處副手共用既有來源；第二、三章特殊裝備政策也接入，但只有實際來源符合時才發放。
- 固定戰鬥種子及獨立的收益種子流，固定取得時間與裝備實例 ID；重新計算同一份工作得到相同結果，不使用真實時間生成裝備 ID。
- 擊殺紀錄在事件引擎確認基礎普通怪 HP 歸零時保存，包含序號、時間、HP=0、實際怪物定義。驗證擊殺總数、時間、身份、死亡終止、隊員狀態與藥水帳本，未完成的怪物不發獎勵。

### 未接入與來源限制

- 建築、菁英、Boss、其專屬收益與通關均不模擬。
- 保留現有離線不掉 HP／MP 藥水、不自動購買藥水的政策，沒有移植在線 addLoot 的藥水掉落。
- 不增加召喚怪額外收益：正式普通怪池沒有目前的召喚者；第三批召喚能力仍保留，但不是新離線收益來源。
- **第三章六區正式普通怪均沒有一般裝備 lootConfig**，共 24 個來源。因此一般裝備政策會略過，不會自行套用第二章裝備池。來源核對在 tmp/offline-4a-normal-loot-sources.json；其中舊 redrock-wastes 標題區不是正式六區，不應把其平原 fallback 當第三章來源。本批沒有修正此既有來源問題或替它定案。
- 第二、三章特殊紫裝目前來源多為菁英／Boss，普通怪離線不會因接上政策就產生不應有的紫裝。

## 2. 存檔與角色寫回

captureDeparture 從現有隊伍建立離開快照，保留實際 1～3 人與邀請時的裝備／技能；不替隊友更新裝備。只有 fighting=true 的快照可產生收益。時間不足 60 秒只推進已處理時間，不執行戰鬥；最多模擬 43,200,000 ms。

收益及消耗先計算至完整角色槽位副本，按 character.id 尋找角色，不依目前畫面選中的槽位寫回。只改實際參戰隊員的狀態，其他槽位保留。

保存 partyMemberState 的 HP、最大 HP、alive、職業資源、護盾、不死族復起、復活剩餘時間。完整動態狀態、冷卻、DOT、寵物、延遲治療、保命共用時間另外保存到 offlinePartyRuntime，附 runId 及模擬時鐘。恢復接口按模擬結束時鐘重新定位截止時間，不啟動真實計時器。

共享 HP 消耗 = hpUsed + reviveUsed；MP 消耗 = mpUsed。先驗證初始與剩餘帳本，再一次扣除背包計數及可用藥水項目，不容許負數。舊存檔可能只有計數而沒有背包項目，沿用舊資料相容方式，不憑空新增藥水。

有升級時必須注入既有 getCharacterStats 計算器；未提供則拒絕結算，避免保存錯誤升級屬性。結算後的最大 HP 可重算，戰鬥模擬屬性維持離開快照。恢復升級後的戰鬥狀態同樣需要既有屬性計算器。

主角死亡立即結束模擬、停止收益；依舊離線政策保存村莊恢復 HP、requiresMapSelectionAfterDefeat，副本退回既有返回地圖並清入場狀態。死亡前的動態戰鬥記錄僅供核對，resumeAllowed=false，不能拿來恢復舊戰鬥。隊友死亡與復活結果仍獨立保留。

## 3. 實際安全機制

資料庫 stardust-offline-stage-a-4a，accounts 與 runs 兩個資料表。

1. 工作 ID 綁定帳戶、主角 ID 與離開時間；完整快照、種子、時間區間、基礎版本先寫入 prepared 紀錄。
2. 模擬在交易外進行，不持有 15 秒存檔交易。
3. 一個 IndexedDB readwrite 交易同時讀取帳戶／工作，檢查 revision 與完整原存檔內容。
4. 同一交易寫入全部角色槽位、副本背包與資源、帳戶新版本，以及 committed 工作與報告。
5. 只在交易 oncomplete 後返回 claimed=true。展示回呼還要核對目前角色 ID；角色已切換就不在其他角色畫面展示。
6. 同工作再次領取返回已存結果，不重新模擬、不再次扣藥水或發獎。
7. 模擬期間若新版在線寫入接口更新帳戶，提交會拒絕舊版本，不覆蓋其修改。

不是 localStorage 讀取／檢查／寫入鎖，也沒有不安全 fallback。真實瀏覽器中的兩個分頁共用同一 IndexedDB，實測只一個新提交，另一個取得 duplicate=true；金幣 10→30、藥水 5→3、revision 0→1 各一次。重新整理後再領仍是 duplicate=true。

### 安全機制的範圍與限制

- **以上保證只涵蓋新的 IndexedDB 存檔接口。原有在線 localStorage 寫入者尚未參加同一交易，不能宣稱正式全遊戲已解決多分頁競爭。** 本批沒有將新結果投影回正式 localStorage，避免跨兩套儲存的部分寫入。
- 正式啟用之前，所有相關在線寫入及離線寫入必須統一到同一權威存檔接口；不能只新增 localStorage 投影並認為安全。
- 同一帳戶的不同角色也共用 revision；同時修改會安全拒絕其中的過期提交，不會覆蓋。重試前應重新確認權威快照，不可強制覆蓋舊工作。
- 同時兩個分頁可能都計算同一工作，只有一個可以提交；目前尚未避免重複 CPU 計算。Worker 階段可加工作持有者協調。
- IndexedDB 無法使用、quota 或交易失敗時拒絕領取，不偷偷退回舊儲存。資料庫被使用者刪除／裝置儲存遭清除不屬於此 exactly-once 保證。
- 目前尚未清理歷史工作；大量結算會增加儲存量，後續需搭配永久時間邊界設計保留政策。

## 4. 失敗恢復

- 模擬／掉落／驗證失敗：prepared 還在，所有遊戲收益與消耗未寫入，原快照及種子可重算。
- 帳戶寫入後、工作記錄前發生錯誤：整筆交易 rollback，沒有獎勵與消耗半套。
- 全部寫入後、畫面顯示前關閉頁面：committed 已保存，下次直接讀結果，不再發放。
- 關閉資料庫再開啟可找回 prepared，使用原種子完成；已 committed 的工作也可重新展示。
- 權威角色資料已變動：拒絕提交，保留其新資料；不自動拿舊快照覆蓋。
- 舊單人存檔匯入只解析／複製，沿用 PartyPolicy 的穩定角色 ID 修復，保留未知欄位、空槽與原離線資料，不更動原 localStorage。

## 5. 驗證

- 完整回歸：206 個測試檔通過、0 失敗，包含第三批 75 個怪物、225 個在線對照與第二批原有技能測試。
- 新收益／狀態測試：31 個案例通過，包括實際 1／2／3 人、60 秒與不足 60 秒、無擊殺、死亡、充足／不足／零藥水、隊友復活、固定種子、升級凍結、Lv45 不降級、材料／符文／裝備／副手、舊存檔、恢復身份及 12 小時上限。
- 真實瀏覽器 IndexedDB 安全檢查：13 個案例通過，包括 20 個並行請求、兩處交易中斷、恢復、重試、版本衝突、關閉資料庫重開、負數拒絕及切換角色展示保護。
- 額外兩個真實分頁競爭與重新整理重領驗證通過。
- 瀏覽器完整三人事件模擬→收益→交易寫回→重領防護通過，60 秒測試結果為 241 次擊殺、482 金幣、63 件測試配置裝備、三瓶 HP 藥水僅扣一次；資料保存與固定種子草稿完全一致。這些是隔離測試配置，不代表實際玩家收益。
- 原正式 claimOfflineRewards 沒有替換，沒有修改在線技能／怪物／掉落平衡。現有回歸全綠；實際登入、角色切換、頁面恢復的正式三人入口尚未啟用，不能把隔離驗證當成其上線驗收。

## 8. 第四批 B 的接點及正式啟用前需求

- settle 的 calculate 可回傳 Promise；prepared.job 是完整可序列化輸入，可交給未来 Worker。沒有實裝 Worker。
- Worker 返回後仍在主頁驗證完整結果，再進同一提交交易；僅消息完成不能算已領取。
- 要把舊在線存檔寫入統一到權威交易接口，並接上可持久保存的離開時間／快照、登入及 visibility 流程，協調多分頁的在線／離線所有權。
- 現有 createBattlePartyMember 會重設 alive、護盾、冷卻，並把 HP0 改為正值；正式恢復必须使用新接口，不能让死亡隊友免費復活。
- 升級後提供現有屬性計算器，恢復保命共用時間、角色冷卻、DOT、寵物及延遲治療；所有權與角色身份必須再次檢查。
- 模擬進度／背景執行、CPU 去重、存檔容量與工作清理，再做正式生命周期驗收。
- 第三章普通裝備 lootConfig 是現有設計來源缺口，需要確認正式裝備池政策，不能在 Worker 實作時順便猜機率。

本批停止於上述接口與隔離驗證，不開始第四批 B，不自行啟用或提交。
