# 第一階段 D-2：存檔路徑統一驗收

驗收日期：2026-10-13。分支 dev；未提交 commit。正式入口未啟用永久角色、未遷移正式存檔，三人離線仍關閉。本報告區分「隔離接線完成」與「正式切換完成」。Lv30 問題已補驗修正，見第 6 節。

## 1. 完成的資料路徑

`script.js` 原本直接讀寫 localStorage 的入口全部改經 `getGameStorage()`。永久服務啟用時使用服務提供的相容投影，未啟用時沿用原本 localStorage。唯一直接取得原生 localStorage 的位置是此路由；未建立由旧資料覆蓋新資料的回退機制。

已接入：角色讀取與保存、建立角色、切換主角、招募／離隊、共用背包、裝備所有權、材料／藥水／配方／符文、在線獎勵與自動保存、登入狀態、版面設定，以及隔離的舊單人離線結算。查看隊友不切換主角。金幣與既有貨幣歸屬不變。

重設使用交易封存原永久模型、退役 ID，再清空目前模型；保留角色與裝備的恢復依據。登出只改登入設定，不刪除角色。現有正式 HTML 沒有 profile/reset 按鈕，相關可選處理及服務接口已接線，驗收以服務操作確認，不新增 UI。個別刪除角色仍使用既有永久政策接口，未新增操作介面。

## 2. 權威來源及設定分流

啟用新服務後，IndexedDB 帳號紀錄的 `permanent` 是角色、共用背包、裝備及編組唯一權威；裝備與背包在同一筆交易變更。localStorage 僅供舊入口及明確要求的副本遷移，不會覆蓋已有永久資料。

設定另存於同一 DB 的 `preferences:<accountId>` 紀錄，使用獨立版本及 CAS。變更版面、登入名或登出，不重写角色模型。舊帳號內 settings 只作相容讀取；設定紀錄存在後以該紀錄為準。遷移時角色與設定在同一筆 IndexedDB 交易寫入；備份先保存完整來源。未修改 IndexedDB schema。

正式入口依本批限制仍使用原生舊存檔。這是尚未正式切換的開關狀態，不代表已清理玩家的舊資料。第四批 A 保留原本工作及交易政策；隔離三人收益未開啟。

## 3. 在線與單人離線收益

舊單人公式抽出共用計算函式，保留 12 小時上限、未滿一分鐘、經驗衰減、金幣、掉落、藥水及敗北回村政策。以原函式副本及相同亂數逐項比較結果，而非用新公式作為測試預期。

隔離的單人接線：先 flush → 保存待結算工作（角色 ID、來源版本、完整模型、原始起訖時間、種子、計算上下文）→ 同一舊公式計算 → 模型與已結算紀錄原子寫入 → 顯示收益。首次工作產生亂數種子；重試使用已保存種子及時間。重複完成工作只回傳確認，不重新套用舊模型。

在線獎勵保存時同步更新離線時間界線；隱藏頁面先停止在線計時再保存。模擬期間不讓在線定時器同時修改角色。寫入失敗、版本衝突會拒絕，不宣稱收益已領取。待結算工作存在時禁止普通帳號變更，防止背包／藥水與收益分開生效。

遇到第四批 A 舊 prepared 工作，要求按原工作政策恢复，不會擅自改為單人或重算三人收益。

## 4. 多分頁及中斷驗證

兩個獨立瀏覽器分頁同時對相同隔離帳號結算：一個成功入帳，另一個收到 duplicate；20000 金幣只增加至 20010，未留 prepared 工作。這是交易安全測試的固定收益，實際舊公式另由整合測試驗證。

同時保存角色：一個成功，另一個 `Concurrent save conflict`。同時保存設定：一個成功，另一個衝突。依靠 IndexedDB readwrite 交易內的版本檢查與 journal，不是 localStorage 的先讀後寫。不同設定與角色版本互不干擾。

注入角色寫入後、journal 寫入後的失敗：收益／藥水／裝備沒有部分寫入，prepared 工作完整留下；重新載入後依原種子與時間恢復。遷移中斷可重試，不重複匯入，完整來源備份保留。原生正式存檔測試前後相同。

瀏覽器正常 reload 已驗證。強制終止瀏覽器或作業系統不保證最後一筆尚未提交的在線變更被保存；未宣稱 beforeunload 能保證落盤。
